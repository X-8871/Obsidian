## 二、 核心维护与作业流程 (Runbook)

### 1. 课程与学科资料处理规范
- **MOC 导航与序列化**：每个学科根目录必须创建 `00-[课程名]复习总览.md`；各子文件夹严格赋予 `01-`、`02-` 等数字前缀；通用卷子答案等笔记必须冠以学科前缀（如 `电工_21-22A卷答案.md`）。
- **图文精细化处理**：
  - **DOCX / 纯文本**：重构 Markdown 层级，大量运用 Callout 提示块、高亮（`==高亮==`）与加粗增强美感。
  - **公式/理科 PDF**：**严禁强行提取乱码纯文本**，必须切为高清 PNG 存入 `附件/` 目录，以长卷 `![[图片.png]]` 形式组装。
  - **大篇幅 PPT/教材**：直接收纳至对应 `附件/` 目录，使用内部双链 `[[文件名.pdf]]` 链接。
- **图片智能纠偏**：默认不自动旋转图片。仅当用户明确要求“处理图片”，或图片名带有“手写”、“卷子”且 `宽 > 高` 时，才执行 90 度旋转矫正为竖版。
- **Frontmatter 属性标配**：每篇课程笔记顶部必须注入标准 YAML：
  ```yaml
  ---
  type: course-note
  domain: course
  course: [学科全称]
  status: active
  tags: [[科目简称], 核心标签...]
  ---
  ```

### 2. 日常日记 (Daily Notes) 归档规范
- **按月折叠归档**：所有 Daily Notes 必须严格按照 `01-Daily/YYYY-MM/YYYY-MM-DD.md` 的层级存放，**严禁在 `01-Daily` 根目录大面积铺开**。

### 3. Markdown 排版与视觉偏好
- **排版要素**：重度使用 Callout 块（`> [!TIP]`、`> [!WARNING]` 等）、`==高亮==` 与 `**粗体**`。
- **万物皆双链**：重度依赖 `[[双向链接]]` 连接知识点，保持知识网状互通。
- **中文物理文件名**：所有笔记文件的物理名称必须使用中文（专有名词可中英结合）。
- **代码导入规范**：代码必须完整包裹在 Markdown 三反引号中（如 ```` ```python ... ``` ````），防止代码注释 `#` 被错误解析为标题。

### 4. 常用模板与快捷键指引

| 快捷键 | 功能 | 存储/模板位置 |
| :--- | :--- | :--- |
| `Ctrl+H` | 创建日报 | `01-Daily/Daily/` |
| `Ctrl+Shift+H` | 创建周报 | `01-Daily/Weekly/` |
| `Alt+T` | 插入模板 | `Temptlaters/` |
| PlanMind 目标中心 | 年度、月度、周度、日度与长期目标 | `08-PlanMind/` |

## 三、 🚫 架构红线与禁忌 (Architectural Redlines)

> [!CAUTION]
> **以下行为为 Vault 运维的绝对高压红线，违者视为严重违规：**

1. **只读与显式授权原则**：
   - 默认以只读态度对待 Vault。对 Vault 进行大范围写入或重排版前，**必须先向用户说明计划并获得明确同意**。
   - 绝不擅自、自发地“整理”、“优化”或“重构”未经用户指定的目录。
2. **防孤岛强制约束（Anti-Orphan Enforcement）**：
   - **创建、重命名或移动任何笔记后，最后一步必须硬性更新与之相关的 `00-索引` 或相关 MOC 文件，彻底杜绝孤岛笔记！**
3. **严禁修改 `.obsidian/` 底层配置**：
   - 严禁擅自修改 `.obsidian/` 下的插件配置与主题，除非用户明确点名要求。
4. **隐私与敏感数据隔离**：
   - **严禁向普通笔记写入明文密码、API Key、Token 等敏感信息**（敏感凭据必须走 `09-AI_Knowledge_Hub/05-Private_Vault` 门禁隔离区）。
   - 严禁擅自处理 `06-个人/个人信息.md` 等隐私文件，除非用户明确点名。
5. **严禁破坏性操作**：
   - 禁止在 Vault 内随意散落生成 AI 临时脚本、日志与中间垃圾文件；
   - 禁止未经用户确认进行批量文件重命名。

## 四、 故障排查、避坑与响应规范

### 1. 常见避坑记录
- **路径空格与中文**：在终端操作时务必注意 Windows 路径的双引号转义；
- **反向链接保护**：修改文件名或调整双链时，必须确保不破坏原有的反向链接关系；
- **编码格式**：全库所有文档必须 100% 保持 UTF-8 编码。

### 2. AI 响应交付标准
- 每次完成 Vault 内的修改或整理任务后，**必须输出清晰的结果摘要**（包括：修改了哪些文件、同步更新了哪些 `00-` 索引 MOC、是否有需要用户后续确认的事项）。
