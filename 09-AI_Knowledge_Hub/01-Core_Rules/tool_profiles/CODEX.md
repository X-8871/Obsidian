# ⚡ CODEX 专属行为规范与避坑档案

> [!IMPORTANT]
> 当 AI 运行在 **OpenAI Codex** 客户端环境中时，除遵循 `[[AGENT_CORE]]` 全局宪法外，必须强制执行本档案中的**工具特异性约束**。

---

## 一、 🖥️ 桌面控制与 Node 运行时生命周期 (Computer-Use & Node REPL)

1. **子进程与管道清理**：
   - 调用 `node_repl` 或 `computer-use` 插件执行系统级操作后，必须确保所有的中间管道与子进程正常结束，避免遗留未释放的进程句柄。
2. **沙箱与权限操作审慎原则**：
   - 当前环境为 Windows Elevated Sandbox 模式，在执行高危系统指令、注册表或文件覆盖前，必须向用户进行显式二次确认。

---

## 二、 🛠️ 代码重构与质量审计准则 (Ponytail 规范)

1. **增量重构原则**：
   - 使用 Ponytail 或技术债分析工具时，禁止大面积推倒已有稳定代码，必须采用小步提交、单元测试覆盖的渐进式演进策略。
2. **ESP32 与 LVGL 专项**：
   - 当涉及 `esp32-s3-lvgl-ui` 开发时，必须遵守项目的物理路径规范，并确保构建命令与专用 Python 3.11 路径对齐。

---

## 三、 📄 跨工具状态同步

- 在 Codex 中完成阶段性编码后，必须在当前项目根目录实时输出/刷新 `HANDOFF.md` 看板，便于 Antigravity 或 OpenCode 接手。

---

## 四、 🧭 Windows 路径与归档命名防误判

> [!CAUTION] 2026-08-27 路径误判事故
> Codex 曾把用户指定的正确归档目录
>
> `C:\Users\22061\Desktop\Person_workdesk\01_work_bench`
>
> 错误识别为
>
> `C:\Users\22061\Desktop\Person\_workdesk`，
>
> 并进一步把只属于总文件夹名的 `01_` 错误添加到 247 个内部文件名。该错误造成归档被放入错误父目录，并需要整体移动、批量恢复文件名以及同步修正文档。

1. **禁止臆测 Windows 路径层级**：
   - `\` 是目录分隔符，`_` 是文件名中的普通字符；`Person_workdesk` 是一个完整目录名，绝不能擅自拆成 `Person\_workdesk`。
   - 不得因为 Markdown 显示、转义符、换行或视觉相似性而改写用户提供的路径。
2. **文件操作前强制核验真实目录**：
   - 执行复制、移动、重命名或删除前，必须对父目录和目标目录分别执行存在性检查，并列出父目录下的同级文件夹名称。
   - 用户提供截图时，必须把截图中的地址栏、窗口标题和实际文件系统结果交叉核对；三者不一致时停止写入并询问用户。
3. **必须复述最终绝对路径**：
   - 在首次产生文件系统写入前，必须使用 Windows 反斜杠格式向用户复述完整目标路径，例如 `C:\Users\22061\Desktop\Person_workdesk\01_work_bench`。
   - 不得仅复述末级名称，也不得用 `/` 替代 `\` 后声称已经精准确认 Windows 物理路径。
4. **目录前缀与文件前缀必须分开理解**：
   - “总文件夹前加 `01_`”只允许把目录命名为 `01_work_bench`，内部源码文件必须保持原名。
   - 未经用户明确说“给每个文件加前缀”，禁止批量修改内部文件名。
5. **操作后必须双向验收**：
   - 确认正确目标目录存在、错误目录不存在、文件总数一致、内部文件名无错误前缀，并逐文件校验哈希。
   - 文档、交接记录和 Obsidian 项目说明中的路径必须同步纠正，禁止保留旧错误路径。
