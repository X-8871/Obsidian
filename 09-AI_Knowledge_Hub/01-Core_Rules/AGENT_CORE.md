# 📜 AGENT_CORE: AI 行为宪法与全局准则

> [!IMPORTANT]
> 本文件是所有接入本环境的 AI Agent（Antigravity、Codex、Workbuddy、OpenCode 等）必须无条件遵循的**最高行为宪法**。

---

## 一、 全局环境与交互设定 (Global Settings)

1. **文件编码 (File Encoding)**: 始终且必须使用 **UTF-8** 进行一切文件的读取、创建和写入，杜绝任何编码乱码。
2. **注释与文档语言 (Language)**: 编写代码时，所有的代码注释、Docstring、解释说明必须统一使用 **简体中文 (zh-CN)**。
3. **时区设定 (Timezone)**: 在处理时间、排期、日志分析或上下文时间时，默认使用 **东八区（南京时间，UTC+8）**。
4. **强制尊称问候 (Mandatory Greeting)**: 在每次回复用户的消息时，必须在回答的最开头第一句严格称呼：“**Hello Wong.**”。

---

## 二、 Obsidian 课程资料与知识库整理规则

当涉及向 Obsidian 知识库导入、整理、排版或迁移资料时，必须自动遵循以下标准化规则：

### 1. 强制数字前缀排序 (Mandatory Prefix Sorting)
- **MOC 置顶**：每个学科或专题根目录必须生成名为 `00-[主题名]复习总览.md` 的核心 MOC 导航页。
- **文件夹序列化**：为打破 Obsidian 默认的拼音/首字母打乱排序，所有模块文件夹必须按照逻辑顺序赋予 `01-`、`02-` 等数字前缀（如 `01-知识总结`、`02-习题集`）。
- **防重名前缀**：对于极易跨学科冲突的通用笔记（如答案、解析），必须自动冠以学科/项目前缀（如 `电工_21-22A卷答案.md`）。

### 2. 多形态文档精细化处理策略 (Smart Format Handling)
- **文字型 (DOCX / 纯文本)**：重构 Markdown 层级结构，必须加入高亮（粗体）、列表和 Callout 引用块（`> [!NOTE]`、`> [!TIP]` 等）提升美感。
- **公式/图表/理科真题 (PDF)**：**绝对禁止强行提取纯文本（会产生严重公式乱码）**。必须将 PDF 逐页切割为高清 PNG 存入所在文件夹的 `附件` 目录，并生成长卷 Markdown 用 `![[图片名.png]]` 语法串联，实现顺畅滚动的图文复习体验。
- **超大型文献/长篇 PPT**：无论资料多大，全部拷贝收编进入对应科目的 `附件` 文件夹，并在索引 Markdown 中使用纯正内部双链 `[[文件名.pdf]]` 建立跳转。**严禁使用外部绝对路径 `file:///`**，确保知识库 100% 独立便携。

### 3. 智能纠偏系统 (Smart Image Rotation)
- 在导入手机拍摄的手写习题或卷子图片时，必须编写自动检测脚本读取宽高比。一旦发现“横躺”（宽 > 高）的照片，强制进行 90 度旋转矫正为竖版 (Portrait)，确保阅读无需歪头。
- 图片命名必须规范化、序列化（如 `[科目简称]习题_01.jpg`）。

### 4. Frontmatter 元数据强制封印 (Metadata Enforcement)
- 创建或迁入的每一篇 Markdown 笔记，顶部必须打上标准的 YAML 属性：
  ```yaml
  ---
  type: course-note
  domain: course
  course: [学科全称/项目名称]
  status: active
  tags: [[科目简称], 核心标签...]
  ---
  ```

## 三、 思考与工程操作底线 (Operational Redlines)

1. **先规划，后执行**：面对复杂重构、大型项目修改时，先出具方案规划并确认，禁止盲目无序更改。
2. **保持架构完整性**：严格遵守各项目在 `03-Project_Runbooks/` 中定义的架构红线，严禁擅自精简或重写核心业务逻辑。
3. **知识路由查阅机制**：
   - 涉及服务器、网络、数据库时 $\rightarrow$ 主动读取 `[[云服务器连接与运维_模板]]`；
   - 涉及特定重要项目时 $\rightarrow$ 主动读取 `03-Project_Runbooks/` 下对应的项目手册；
   - 涉及多 AI 任务切换时 $\rightarrow$ 严格执行 `[[HANDOFF_PROTOCOL]]`。
4. **大型项目实时动态交接看板 (Continuous Live Handoff)**：
   - 在推进大型项目、跨模块重构或多步骤任务时，AI **必须在每一个阶段性里程碑达成后、重大决策变更时、或本轮会话结束前，实时更新项目根目录的 `HANDOFF.md`**。
   - 严禁把交接记录拖到任务全部做完才写，确保随时遭遇中断或切换工具时，上下文 100% 完整可衔接。
5. **项目物理地址与仓库显式声明 (Mandatory Absolute Path & Repo)**：
   - 编写或维护任何项目的运行手册（Runbook）、交接文档（HANDOFF.md）或环境说明时，**必须在文档开头显式、精准地写明本项目的本地绝对物理路径（如 `C:/Users/22061/Desktop/...`）及远端 Git 仓库地址**。
   - 严禁使用模糊指代（如“当前目录”或仅写相对路径），确保任何新接手的 AI 能在无须提问的情况下瞬间定位到磁盘真实位置。

## 四、 绝密隔离区访问禁令 (Zero-Trust Privacy Protocol)

> [!CAUTION]
> **私密隔离区门禁锁（最高安全级别）**：
> 1. `05-Private_Vault/` 目录属于物理与逻辑双重绝密隔离区。
> 2. **严禁主动扫描与读取**：未经用户在当前对话中明确发出显式授权指令（例如：“`授权访问私密库`”或“`读取 Private_Vault`”），任何 AI 绝对禁止主动检索、读取、分析或在回复与日志中打印该目录下的任何文件内容。
> 3. **严禁硬编码泄露**：在任何生成的代码、测试脚本或配置文件中，绝对严禁将敏感凭据直接硬编码，必须强制引导使用环境变量（如 `os.getenv`）或外部安全载入。
