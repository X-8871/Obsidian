## 🗓️ Day 1（09-01）：RGB → Gray 灰度转换

### 最终目标
显示器的画面变成灰度图，按键切换原图/灰度。

### 一步一步怎么做

**第 1 步：从项目二复制工程**
- 复制项目二的整个 Vivado 工程文件夹
- 改名为 `image_pipeline`

**第 2 步：写 HLS 灰度转换核**

```c
// 灰度公式：Gray = 0.299*R + 0.587*G + 0.114*B
// 用整数近似，不用浮点
unsigned char gray = (R*77 + G*150 + B*29) >> 8;
```

- 新建 HLS 模块 `rgb2gray`
- 输入：R, G, B 三个分量
- 输出：灰度值（和 R 相同位数，赋值给 R=G=B）

**第 3 步：集成到 HDMI 管线**
- 从 DDR3 读一个像素 → 灰度转换 → 写回 DDR3
- 按键切换：
  - 按键按下 → 显示灰度图
  - 按键松开 → 显示原图

**第 4 步：综合 + 烧录 + 验证**
- 显示器上图案变成灰度，确认颜色转换正确

## 🗓️ Day 2（09-02）：Sobel 边缘检测

### 最终目标
显示器显示边缘检测结果，能看到图案的轮廓。

### 一步一步怎么做

**第 1 步：理解 Sobel 算子**
- Sobel 检测图像边缘 = 计算像素值的变化率
- 用两个 3×3 卷积核分别检测水平和垂直边缘
- 最终结果 = sqrt(Gx² + Gy²)

**第 2 步：理解行缓存（Line Buffer）**
- Sobel 需要 3×3 邻域 → 需要存 3 行像素数据
- 用 HLS 的 `LineBuffer` 实现：
  - 第 1 行进来 → 存到 Line 1
  - 第 2 行进来 → 存到 Line 2
  - 第 3 行进来 → 和 Line 1/2 组成 3×3 窗口

**第 3 步：写 HLS Sobel 核**
- 搜 "Vitis HLS Sobel example" 找参考代码
- 或者搜 "HLS line buffer sobel" 找实现
- 核心代码结构：
```c
// 伪代码
LineBuffer<3, 3, unsigned char> buf;
for(row = 0; row < height; row++) {
    for(col = 0; col < width; col++) {
        buf.shift_pixel(row, col, gray_val);
        if(row >= 2 && col >= 2) {
            sobel_val = abs(Gx) + abs(Gy);  // 近似
            // 输出 sobel_val
        }
    }
}
```

**第 4 步：集成到管线**
- 原图 → 灰度 → Sobel → 显示
- 按键切换：原图 / 灰度 / 边缘

### 今天产出物
- [ ] 显示边缘检测结果
- [ ] HLS Sobel 核综合通过

## 🗓️ Day 3（09-03）：均值滤波 + 高斯模糊

### 最终目标
画面能变模糊，两种模糊方式可切换。

### 一步一步怎么做

**第 1 步：写 HLS 均值滤波核**
- 3×3 均值：9 个像素求和再除以 9
- 和 Sobel 一样需要行缓存
- 区别：Sobel 算差值，均值算平均值

```c
// 均值滤波伪代码
sum = p[0][0] + p[0][1] + p[0][2]
    + p[1][0] + p[1][1] + p[1][2]
    + p[2][0] + p[2][1] + p[2][2];
avg = sum / 9;
```

**第 2 步：写 HLS 高斯模糊核**
- 3×3 高斯核：
```
[1  2  1]
[2  4  2] / 16
[1  2  1]
```
- 比均值滤波更平滑（中间像素权重更高）
- 边缘保留效果更好

**第 3 步：集成到管线**
- 按键切换：原图 / 灰度 / 边缘 / 均值滤波 / 高斯模糊

### 今天产出物
- [ ] 两种滤波效果正常显示

## 🗓️ Day 4（09-04）：流水线串联 + DATAFLOW

### 最终目标
多个处理级串联成流水线，各级并行工作。

### 一步一步怎么做

**第 1 步：串联处理流水线**
```
原图 → 灰度 → 均值滤波 → Sobel → 输出
```
- 每一级独立成一个 HLS 函数
- 用 `hls::stream` 连接各级
- 不是先处理完一帧再下一帧，而是像素级流水

**第 2 步：加 DATAFLOW pragma**
```c
#pragma HLS DATAFLOW
```
- 让各级并行执行
- 不加 DATAFLOW：串行，一级处理完才下一级
- 加 DATAFLOW：并行，各级同时工作

**第 3 步：对比性能**
- 看综合报告里的 II（Initiation Interval）
- 不加 DATAFLOW 的 II = ？
- 加 DATAFLOW 的 II = ？
- 记录对比结果

## 🗓️ Day 5（09-05）：可调参数 + 交互控制

### 最终目标
用串口调参数，实时看到效果变化。

### 一步一步怎么做

**第 1 步：Sobel 阈值可调**
- 串口发 `edge_thresh 50`
- 边缘检测结果低于阈值 → 不显示（减少噪点）
- 阈值越高，显示的边缘越少

**第 2 步：模糊强度可调**
- 串口发 `blur 3` → 3×3 模糊
- 串口发 `blur 5` → 5×5 模糊（更模糊，消耗更多资源）

**第 3 步：色彩增强**
- 饱和度调节：RGB → HSV → 调整 S 分量 → RGB
- 串口发 `saturation 1.5` → 饱和度增加 50%
- 简单实现：`R = gray + (R - gray) * sat`

- [ ] 串口可调 Sobel 阈值
- [ ] 串口可调模糊强度

## 🗓️ Day 6（09-06）：性能优化 + 资源分析

### 最终目标
分析资源消耗，优化到最高帧率。

### 一步一步怎么做

**第 1 步：分析综合报告**
- 打开综合报告，记录：
  - LUT 消耗：xxx / 20800 (xx%)
  - DSP 消耗：xxx / 90 (xx%)
  - BRAM 消耗：xxx / 50 (xx%)
  - 最慢的一级是哪个？

**第 2 步：优化瓶颈**
- 如果 PIPELINE 没加 → 加 PIPELINE II=1
- 如果 BRAM 访问太多 → 减少不必要的读写
- 如果行缓存太大 → 缩小到实际需要的尺寸

**第 3 步：帧率估算**
- 640×480 @60fps = 每像素 26ns 内处理完
- 看综合报告的 Latency（处理一个像素需要多少时钟周期）
- 50MHz 时钟 = 20ns 每周期
- 如果 Latency ≤ 1 → 能跑 60fps
- 如果 Latency > 1 → 当前帧率 = 50MHz / (Latency × 640 × 480)

- [ ] 优化后的综合报告
- [ ] 知道当前帧率上限
