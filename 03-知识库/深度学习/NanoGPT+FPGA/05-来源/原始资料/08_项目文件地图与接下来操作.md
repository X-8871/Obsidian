## 下一个 AI 的操作顺序

1. 先阅读 00_AI接手说明.md。
2. 阅读 14 的最新任务计划和 15 的真实单 Token 实验记录。
3. 不再重复参数锁定、Vivado 初次构建、Vitis 初次构建和 JTAG 单 Token 基线；这些已经完成。
4. 先完成 SD 卡 `BOOT.bin` 脱机启动与 UART 就绪信息验证。
5. 依次完成 1、8、20、200 Token 单板生成，不能直接从 1 跳到 200。
6. 对 20/200 Token 保存板端 Token ID 序列，并与 Python Q30 逐 Token 对齐。
7. 连续运行三次，记录稳定性、首 Token 延时、总耗时和 Token/s。
8. 主线全部完成且有时间时，再从打开 Vivado 开始，用 Vivado/Vitis GUI 复现一次部署，尽量不使用 PowerShell。

## 重要限制

- 不能把 Python 自一致性 mismatch=0 写成 FPGA 通过。
- 不能把历史旧版本的 mismatch=0/200 直接套到当前模型。
- 不能覆盖原始 ckpt.pt、现有 bitstream、DDR 镜像和历史报告；修改前先打包。
- 训练、Python 实验必须使用：D:/FPGA/NanoGPT/venv-gpu。
- 当前只能写成“JTAG 单 Token 板级通过”；在实际看到脱机启动、UART 和多 Token 日志前，不能写成“离线多 Token 部署完成”。
