# NanoGPT 项目重点实验路线与验收清单

> 本文件只整理仓库内部对最终成果最重要的实验：Python 量化、Q30 对齐、Vivado PL、HLS、Vitis PS 和真实板级联调。
>
> model.py、train.py、sample.py 的基础学习仍按单独的七章学习路线进行，本文件不重复展开。

## 一、项目最终目标

~~~text
FP32 nanoGPT
  → Python 端 INT8 量化
  → Q30 定点参考模型
  → Vivado PL Transformer 硬件
  → Vitis PS 裸机控制程序
  → DDR + UART + Zynq 开发板
  → 板端 Token 输出与 Python 参考结果一致
~~~

本项目最终要证明四件事：

1. 模型可以从 FP32（32-bit Floating Point，32 位浮点数）转换为 INT8（8-bit Integer，8 位整数）。
2. INT8/Q30（定点数格式）模型的质量损失在可接受范围内。
3. FPGA 上的六层 Transformer 计算结果与 Python 参考结果一致。
4. PS+PL（Processing System + Programmable Logic，处理系统加可编程逻辑）可以通过 UART（Universal Asynchronous Receiver/Transmitter，通用异步收发器）完成真实文本生成。

## 三、P0-1：Python 端 W8A8 量化包生成

### 目标

把真实 Shakespeare nanoGPT checkpoint（检查点）中的 Linear（线性层）和 Embedding（嵌入层）权重转换为 INT8，并保存 scale（缩放因子）和激活量化配置。

### 真实入口

~~~text
D:/FPGA/NanoGPT/nanogpt-zynq-backups-main/01_VSCode_Python/01_quantize_int8.py
~~~

依赖文件：

~~~text

python/nanoGPT/out-shakespeare-char/int8_reference/quant_config.json
python/nanoGPT/tools/eval_int8_reference.py
~~~

### 需要理解的代码

- load_checkpoint_model()：加载真实 FP32 模型。
- activation_scales：读取激活校准尺度。
- build_quantized_model()：构造 W8A8（8-bit Weight/8-bit Activation，8 位权重/8 位激活）模型。
- int8_tensors：统计 INT8 权重。
- scale_tensors：统计缩放因子。
- torch.save()：保存量化演示包。

### PowerShell 操作

& "D:/FPGA/NanoGPT/venv-gpu/Scripts/python.exe" "./01_quantize_int8.py" --force
~~~

### 验收证据

重点查看：

~~~text

~~~

仓库已有参考数据：

|---|---:|
| 量化模块数 | 27 |
| FP32 状态大小 | 43,080,192 B |
| INT8 权重大小 | 10,765,056 B |

## 四、P0-2：FP32 与 Q30 INT8 Token 对齐

### 目标

输入相同 Prompt（提示词），分别运行：

- GitHub/nanoGPT FP32 采样路径。
- 严格硬件对齐的 INT8 Q30 参考路径。

比较生成 Token ID（Token 编号）和最终文本，理解量化模型为什么可能与 FP32 产生不同字符。

### 真实入口

~~~text
D:/FPGA/NanoGPT/nanogpt-zynq-backups-main/01_VSCode_Python/02_token_console.py
~~~

依赖文件：

~~~text
python/nanoGPT/out-shakespeare-char/ckpt.pt
python/nanoGPT/out-shakespeare-char/int8_reference/int8_state_dict.pt

~~~

### PowerShell 操作

~~~powershell

& "D:/FPGA/NanoGPT/venv-gpu/Scripts/python.exe" "./02_token_console.py" --prompt "ROMEO:" --max-new-tokens 3
~~~

### 需要观察

- 输入字符。
- 输入 Token ID。
- INT8 Q30 每一步的 Token ID。
- FP32 每一步的 Token ID。
- 两种模式的完整输出文本。
- demo_outputs/last_token_run.json。

### 验收标准

- Prompt 中的每个字符都能在 stoi（string-to-integer，字符串到整数）中找到。
- itos（integer-to-string，整数到字符串）能够把 Token ID 还原为字符。
- INT8 参考模型可以完整运行，不出现缺少 scale、词表或 checkpoint 的错误。
- 能解释 FP32 与 INT8 生成文本不同不一定代表程序错误，要结合 logits 误差、量化误差和 Token mismatch 分析。

## 五、P0-3：Vivado PL 架构与签核结果检查

### 目标

看懂 FPGA 侧 Transformer 数据流，并能从已有报告判断工程是否达到签核条件。

### 真实入口

~~~text
D:/FPGA/NanoGPT/nanogpt-zynq-backups-main/02_Vivado_PL/README.md
D:/FPGA/NanoGPT/nanogpt-zynq-backups-main/vivado_project/nano_gpt.xpr
D:/FPGA/NanoGPT/nanogpt-zynq-backups-main/artifacts/VALIDATION.md
~~~

### 重点观察的数据流

~~~text
Zynq PS
  → DDR
  → AXI DMA / SmartConnect
  → Embedding
  → LayerNorm
  → Q/K/V Projection
  → QKT Attention
  → Output Projection
  → FFN
  → LM Head Argmax
~~~

- AXI：Advanced eXtensible Interface，高级可扩展接口。
- DDR：Double Data Rate，双倍数据速率存储器。
- DMA：Direct Memory Access，直接存储器访问。
- FFN：Feed-Forward Network，前馈网络。
- Argmax：选择最大分数对应的类别编号。

### 操作要求

1. 打开 Vivado 工程。
2. 查看 Block Design 中 PS、DDR、DMA 和 Transformer 核的连接。
3. 查看 timing_post_route.rpt。
4. 查看 utilization_post_route.rpt。
5. 对照 artifacts/VALIDATION.md 解释时序、资源和一致性指标。

### 验收标准

- 能指出顶层是 system_wrapper。
- 能解释 WNS（Worst Negative Slack，最差负时序裕量）、TNS（Total Negative Slack，总负时序裕量）和 WHS（Worst Hold Slack，最差保持裕量）。
- 能读出 100 MHz 时钟、WNS +0.181 ns、TNS 0、WHS +0.036 ns。
- 能读出 LUT、FF、BRAM、DSP 资源占用率。
- 能解释六层 hidden mismatch 0/4224 的含义。

### 注意事项

已有最终 bitstream 和 routed DCP（布局布线检查点），教学查看不要求立刻重新综合。重新实现耗时较长，并且 open_vivado_project.ps1 内部使用了旧的 Vivado 路径 F:/Vivado2025.2/...，当前机器运行前必须先确认工具路径。

## 六、P0-4：Vitis PS Workspace 编译

### 目标

理解 PS 软件如何控制 PL：字符编解码、DDR 地址配置、寄存器启动、状态轮询和 UART 输出。

### 真实入口

~~~text
D:/FPGA/NanoGPT/nanogpt-zynq-backups-main/vitis/README.md
D:/FPGA/NanoGPT/nanogpt-zynq-backups-main/vitis/workspace_sources/ps_mailbox_runner/src/main.c
D:/FPGA/NanoGPT/nanogpt-zynq-backups-main/ps/src/main.c
~~~

### 关键术语

- PS：Processing System，处理系统。
- PL：Programmable Logic，可编程逻辑。
- ELF：Executable and Linkable Format，可执行与可链接格式。
- BSP：Board Support Package，板级支持包。
- XSA：Xilinx Support Archive，Xilinx 硬件平台归档文件。

### 操作流程

1. 从 Vivado 工程导出硬件平台。
2. 创建或刷新 Vitis Workspace。
3. 创建 ps7_cortexa9_0 平台和 standalone BSP。
4. 导入 main.c、startup.S 和 lscript.ld。
5. 在 Vitis 中执行 Clean 和 Build All。

### PowerShell 入口

~~~powershell
Set-Location -LiteralPath "D:/FPGA/NanoGPT/nanogpt-zynq-backups-main/vitis"
& "./create_or_refresh_workspace.ps1"
& "./open_vitis.ps1"
~~~

### 验收标准

- Vitis GUI 构建错误数为 0。
- 生成 PS ELF 文件。
- 能解释 main.c 如何把 Token、权重、scale 和 DDR 地址交给 PL。
- 能解释 PL 完成后 PS 如何读取 Argmax Token 并通过 UART 输出。

### 当前状态

仓库已有 Vitis GUI 构建通过记录，但这只证明本机软件工程闭环，不等于真实开发板已经下载并运行成功。

6. 连续运行三次 Token 和性能 profile（性能剖析）稳定。

## 八、P1：HLS 四个算子实验

### 目标

理解 C/C++ 算法如何通过 HLS 转换为可复用的 FPGA IP（Intellectual Property，知识产权核）。

### 实验清单

| 算子 | 源文件 | 测试文件 | 重点 |
|---|---|---|---|
| LayerNorm | hls/source/layernorm_kernel/layernorm_kernel.cpp | tb_layernorm_kernel.cpp | 均值、方差、定点归一化 |
| GELU + Embedding | hls/source/gelu_embed_kernel/gelu_embed_kernel.cpp | tb_gelu_embed_kernel.cpp | LUT、激活函数和词向量查表 |
| 16×16 MatMul | hls/source/tiled_matmul/tiled_matmul.cpp | tb_tiled_matmul.cpp | INT8 乘法、INT32 累加和分块 |
| MHA | hls/source/mha_kernel/mha_kernel.cpp | tb_mha_kernel.cpp | Q/K/V、多头注意力和定点缩放 |

- LUT：Look-Up Table，查找表。
- MHA：Multi-Head Attention，多头注意力。
- INT32：32-bit Integer，32 位整数，常用于乘加累积。

### 每个算子的完成标准

1. C Simulation（C 仿真）通过。
2. C Synthesis（C 综合）通过。
3. 查看延迟、资源和接口。
4. 将 C++ 结果与 Python/定点参考结果比较。
5. 记录综合生成 IP 的时钟约束和顶层函数。

### 当前阻碍

hls/README.md 已记录当前 Vitis Unified IDE 的 Windows C 仿真启动器会错误调用 Unix 版 loader，因此先解决工具启动器问题，再判断算法是否正确。
