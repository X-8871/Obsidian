## 2. 术语说明

| 术语 | 全称 | 中文含义 |
|---|---|---|
| FP32 | 32-bit Floating Point | 32 位浮点数，作为高精度参考 |
| INT8 | 8-bit Integer | 8 位整数，用于保存量化后的权重或激活值 |
| W8A8 | Weight 8-bit Activation 8-bit | 权重 8 位、激活值 8 位 |
| Q30 | Fixed-point format with 30 fractional bits | 保留 30 位小数的定点格式 |
| PPL | Perplexity | 困惑度，衡量语言模型预测难度 |
| LUT | Look-Up Table | 查找表，例如 GELU 或 Attention 指数查找表 |
| FPGA | Field-Programmable Gate Array | 现场可编程门阵列 |
| RTL | Register-Transfer Level | 寄存器传输级硬件描述 |
| checkpoint | 模型检查点 | 保存模型参数和配置的文件 |
| activation tensor | 激活张量 | 模型运行时各层产生的中间数据 |
| scale | 缩放因子 | 在浮点数和整数之间进行比例转换的数值 |
| mismatch | 不匹配数量 | 两组数据逐元素比较时数值不同的元素数量 |

量化的基本关系是：

```text
浮点值 x
  → q = round(x / scale)
  → INT8 整数 q

近似恢复：
x ≈ q × scale
```

没有 scale 时，只有 INT8 数字，无法知道它原来代表多大的浮点数。

## 6. 实验一：生成 W8A8 量化包

### 6.1 方法和步骤

1. 加载真实 ckpt.pt。
2. 对 Linear（线性层）权重进行逐输出通道量化。
3. 对 Embedding（嵌入层）权重进行逐行量化。
4. 保存 INT8 权重、weight scale（权重缩放因子）和激活量化配置。
5. 比较 FP32 与 INT8 的 loss 和 PPL。

### 6.2 PowerShell 命令

```powershell
Set-Location -LiteralPath "D:\FPGA\NanoGPT\nanogpt-zynq-backups-main\01_VSCode_Python"
& "D:\FPGA\NanoGPT\venv-gpu\Scripts\python.exe" ".\01_quantize_int8.py" --force
```

### 6.3 结果

| 项目 | 结果 |
|---|---:|
| 量化模块数 | 27 |
| INT8 张量数量 | 27 |
| scale 张量数量 | 52 |
| FP32 状态大小 | 43,080,192 字节 |
| INT8 权重大小 | 10,765,056 字节 |
| scale 大小 | 84,588 字节 |
| FP32 loss | 1.466374 |
| INT8 loss | 1.506177 |
| FP32 PPL | 4.333494 |
| INT8 PPL | 4.509458 |
| PPL 回退 | 4.060572% |
| 质量门槛 | 小于 10%，PASS |

### 6.4 结果解释

INT8 的 PPL 比 FP32 略高，说明量化产生了误差；但回退只有约 4.06%，小于 10% 的质量门槛，因此量化质量通过。

### 10.3 补充实验：统一采样并比较 20 个 Token

#### 实验目的

前面的长序列比较中，FP32（32-bit Floating Point，32 位浮点）和 Q30/INT8 使用的采样方式可能不同。随机采样会使两条生成路径即使分数接近，也可能选择不同的 Token。因此先暂时统一采样方式，单独观察量化计算对生成结果的影响。

#### 临时实验方法

本次比较时，临时将两条路径都改为 greedy argmax（greedy：贪心；argmax：argument maximum，取分数最大值的索引）：

- FP32 路径：使用 `torch.argmax` 选择最后一个位置分数最大的 Token。
- Q30/INT8 路径：使用硬件整数分数的最大值选择 Token。
- 暂时关闭 temperature（温度）、Top-k、重复惩罚和随机抽样。
- 比较数量设置为 20 个 Token。

PowerShell 命令：

```powershell
Set-Location -LiteralPath "D:\FPGA\NanoGPT\nanogpt-zynq-backups-main\01_VSCode_Python"
& "D:\FPGA\NanoGPT\venv-gpu\Scripts\python.exe" ".\02_token_console.py" --prompt "everything with a man" --max-new-tokens 20
```

#### 实验结果

| 项目 | 结果 |
|---|---:|
| 请求比较数量 | 20 个 Token |
| 实际比较数量 | 20 个 Token |
| 一致数量 | 19 个 Token |
| 不一致数量 | 1 个 Token |
| 匹配率 | 95% |
| 首个不一致位置 | 第 20 个 Token |

生成 Token ID：

```text
INT8-Q30: [1, 58, 46, 39, 58, 1, 61, 43, 1, 57, 46, 53, 59, 50, 42, 1, 57, 43, 43, 0]
FP32:     [1, 58, 46, 39, 58, 1, 61, 43, 1, 57, 46, 53, 59, 50, 42, 1, 57, 43, 43, 1]
```

生成文本：

```text
INT8-Q30: everything with a man that we should see\n
FP32:     everything with a man that we should see 
```

前 19 个 Token 完全一致，只有第 20 个 Token 不一致。这个结果说明：在排除随机采样差异后，当前 Python Q30 参考路径与 FP32 路径的生成结果高度接近；第 20 个位置可能是量化误差使两个候选 Token 的分数排序发生了变化。该实验仍然是 Python 对 Python 的比较，不能直接说明 FPGA 或 RTL（Register-Transfer Level，寄存器传输级）已经对齐。

#### 实验后恢复

记录完统一贪心实验后，已将 `02_token_console.py` 的采样恢复为原来的采样逻辑，同时保留比较上限为 20 个 Token：

- FP32：恢复 nanoGPT `sample.py` 风格的温度、Top-k 和随机抽样。

因此，Markdown 中本节记录的是“统一贪心采样”的历史实验结果；后续运行脚本时，代码已经回到原来的采样模式。

## 11. 阶段文件格式验证

在 simulate_bittrue_dynamic_int8.py 的阶段保存循环中加入临时输出，实际结果为：

```text
[StageCheck] name=layer_00_input shape=(256, 384) elements=98304 dtype=int8 bytes=98304
[StageCheck] name=layer_00_gelu_in shape=(256, 1536) elements=393216 dtype=int8 bytes=393216
[StageCheck] name=ln_f shape=(256, 384) elements=98304 dtype=int8 bytes=98304
```

其中 dtype 是 data type（数据类型），nbytes 是 number of bytes（占用字节数）。

| 文件 | 形状 | 元素数 | .bin 大小 |
|---|---|---:|---:|
| layer_00_input.bin | (256, 384) | 98,304 | 98,304 字节 |
| layer_00_gelu_in.bin | (256, 1536) | 393,216 | 393,216 字节 |
| ln_f.bin | (256, 384) | 98,304 | 98,304 字节 |

layer_00_gelu_in 的第二维是 1536，因为 MLP 先从 384 维扩展到 4 × 384 = 1536 维。

.bin 保存原始 INT8 二进制数据，主要用于 Python 读取和比较；.mem 保存逐行十六进制文本，主要用于 FPGA 存储器初始化或硬件仿真。


## 12. 遇到的问题与解决方法

### 问题一：找不到阶段文件

错误表现：

```text
FileNotFoundError:
layer_00_input_dynamic_i8.bin
```

原因是旧脚本只查找带 _dynamic_i8.bin 后缀的文件，而当前输出文件实际命名为 layer_00_input.bin。

解决方法：在 simulate_bittrue_dynamic_int8.py 中增加兼容读取逻辑，使脚本依次查找：

```text
<stage>_dynamic_i8.bin
<stage>.bin
```

同时增加 --hardware-root 参数，用来明确指定当前版本的 Q30 硬件参数目录。

### 问题二：旧参考文件比较结果严重不一致

旧参考文件使用的 checkpoint、INT8 权重或 scale 与当前模型版本不同。即使文件名相同，只要权重版本不同，中间激活值就会不同。

解决方法：使用当前的 ckpt.pt、int8_state_dict.pt 和动态 summary.json，重新生成当前版本的硬件参数和阶段参考文件。

### 问题三：硬件参数目录缺少 Attention 指数 LUT

参数导出脚本不会生成该固定查找表，因此复用了项目已有的 attn_exp_neg_q6_q4.mem。该文件是固定函数表，不包含模型权重。

### 问题四：真实 FPGA 独立比较尚未完成

当前的 mismatch=0 是 Python 自一致性结果。还没有把当前版本的 Python 阶段文件与 FPGA 或 RTL 输出逐层比较，因此不能写成“FPGA 对齐通过”。
