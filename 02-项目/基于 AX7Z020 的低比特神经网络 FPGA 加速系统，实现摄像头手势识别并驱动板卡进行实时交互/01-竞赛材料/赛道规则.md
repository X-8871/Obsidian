# AMD FPGA 创新设计赛道规则

> 本文件整理 `D:\FPGA_Competition\AMD.pdf` 中与本作品直接相关的要求。原始 PDF 保留在 D 盘，重要结论标注 PDF 页码；报名、提交和评分细则以后续官方公告为准。

## 1. 我们选择的赛道

- 大赛方向：FPGA 创新设计赛道。
- AMD 内部路线：自主选题赛道，不是 RTL/HLS 本地智能体设计赛道，也不是具身智能赛道。
- 组别：初级组/高级组需按队伍学历和报名审核结果确认；具体器件和作品要求以报名后台为准。[PDF 第 22 页]
- 当前作品：基于 AX7Z020 的低比特神经网络 FPGA 加速系统，实现摄像头手势识别并驱动板卡进行实时交互。

自主选题赛道要求完成一件完整、可复现、可演示的 FPGA 作品，重点考察逻辑设计、状态机、时序约束、接口协议、软硬件协同、功能正确性、实测数据和工程完整度。[PDF 第 22—23 页]

## 2. 对本作品的硬性要求

- [ ] 在提交物中声明具体 FPGA/Zynq 器件型号。
- [ ] 作品必须在真实板卡上跑通，并提供实测输出，不能只停留在仿真。[PDF 第 23 页]
- [ ] 使用 Vivado/Vitis 2026.1 或 2025.2；如使用其他版本，必须在报告中说明并保证复现。[PDF 第 23 页]
- [ ] 提交完整工程文件、源码、仿真或验证结果、综合与实现报告、上板工程、运行脚本、实测输出和参考结果对比。[PDF 第 24 页]
- [ ] 提供可复现的构建脚本，确保他人能够从零开始重建工程。[PDF 第 24—25 页]
- [ ] 提交大模型协作记录，包括提示词、模型回答和自我纠错轨迹。[PDF 第 23—24 页]
- [ ] 将协作过程中沉淀的经验整理成 `skill/` 技能包，并写明适用范围、使用方法、已验证效果和失效边界。[PDF 第 24 页]
- [ ] 工程仓库的目录名和文件名使用纯英文、数字、下划线或连字符；中文只放在文档正文中。[PDF 第 24—25 页]
- [ ] 强烈建议在 GitHub 或 Gitee 开源，并使用允许再分发的开源协议。[PDF 第 23 页]

## 3. 评分关注点

| 评测项 | 权重 | 对本作品的对应证据 |
|---|---:|---|
| 创新性与应用价值 | 30 | 低比特视觉指令识别、板卡闭环和明确应用场景 |
| 性能与资源优化效果 | 20 | INT8 与软件基线的准确率、延迟、FPS、LUT/FF/BRAM/DSP 对比 |
| 功能正确性与设计完整性 | 20 | 仿真、综合、上板、连续运行和异常处理 |
| 大模型协作与技能包 | 15 | AI 协作日志、RTL/量化排障方法、可复用 Skill |
| 文档质量与可复现性 | 15 | README、构建脚本、目录说明、报告和原始证据 |

以上权重来自选题指南自主选题赛道评分表；具体评分公式和阈值以评分细则为准。[PDF 第 25 页]

## 4. 官方推荐工程结构

```text
project_name/
├─ README.md
├─ src/       # RTL、HLS、PS 侧软件
├─ sim/       # 仿真脚本和结果
├─ build/     # 构建脚本、综合实现报告、上板产物
├─ board/     # 板卡资料、测试数据和参考结果
├─ data/      # 数据集、输入样例和标签
├─ skill/     # 可复用技能包
└─ report/    # 设计报告和 AI 协作记录
```

该结构是官方推荐而非强制；本项目的 D 盘工程目录已经按此结构补齐，并保留 `vivado/`、`vitis/`、`verification/` 作为开发阶段工作目录。[PDF 第 24—25 页]
