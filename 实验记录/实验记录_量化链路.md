## 三、实验方法

本章按照以下链路验证：

FP32 checkpoint
 ↓
INT8 权重和激活量化
 ↓
动态激活 scale 校准
 ↓
Q30 硬件参数生成
 ↓
固定 scale 的 Python Q30 参考计算
 ↓
阶段数据和 Token 对比
 ↓
后续与 FPGA/RTL 结果对齐

量化基本公式：

q = round(x / scale)
x ≈ q × scale

其中 x 是浮点值，q 是 INT8 整数，scale 是缩放因子。

## 四、实验一：Python 端 W8A8 量化包生成

### 1.1 生成 W8A8 量化包

方法：加载真实 ckpt.pt，量化 Linear（线性层）和 Embedding（嵌入层）权重，保存 INT8 权重、权重 scale 和激活量化配置。

命令：

Set-Location -LiteralPath "D:\FPGA\NanoGPT\nanogpt-zynq-backups-main\01\_VSCode\_Python"
& "D:\FPGA\NanoGPT\venv-gpu\Scripts\python.exe" ".\01\_quantize\_int8.py" --force

### 1.2 生成动态 INT8 阶段数据

方法：使用当前 checkpoint 和 INT8 状态字典运行 Prompt，测量各阶段激活范围并生成动态 scale。

主要输入：

Prompt: everything with a man
new-tokens: 1
decode: greedy

### 1.3 生成 Q30 硬件参数

方法：读取动态 scale，将其转换为 Q30 乘法参数、LayerNorm（Layer Normalization，层归一化）参数、残差参数和 GELU（Gaussian Error Linear Unit，高斯误差线性单元）配置。

## 五、实验二：FP32 与 Q30 INT8 Token 对齐

### 2.1 运行固定 Q30 Python 参考模型

方法：使用固定 scale、INT8 权重和硬件 Q30 参数运行模型，保存各阶段 INT8 数据和最终 Token。

### 2.2 进行 Python 自一致性比较

方法：重新读取上一次生成的阶段 .bin 文件，与本次 Python Q30 输出逐元素比较，统计 mismatch（不匹配元素数量）、平均误差和最大误差。

### 2.3 统一采样比较 20 个 Token

方法：临时将 FP32 和 Q30/INT8 都改为 greedy argmax（贪心取最大分数），关闭温度、Top-k 和随机采样，比较 20 个 Token。

命令：

Set-Location -LiteralPath "D:\FPGA\NanoGPT\nanogpt-zynq-backups-main\01\_VSCode\_Python"
& "D:\FPGA\NanoGPT\venv-gpu\Scripts\python.exe" ".\02\_token\_console.py" --prompt "everything with a man" --max-new-tokens 20

实验记录完成后，已将 02\_token\_console.py 恢复为原来的温度、Top-k、重复惩罚和随机采样模式；比较上限仍为 20 个 Token。

## 八、实验问题

### 实验一相关问题：阶段文件名称不一致

脚本原来只查找 \_dynamic\_i8.bin，但实际输出文件为 .bin，导致找不到文件。已增加兼容读取逻辑，同时支持两种文件名。

### 实验一相关问题：旧硬件参数与当前模型版本不同

旧 Vivado 硬件参数和当前 Python Q30 参数的权重指纹不同，不能混合使用。部署 FPGA 前必须确保 checkpoint、INT8 权重、scale、DDR 镜像和 Python 参考模型来自同一版本。

### 实验二相关问题：采样方式会影响 Token 对比

随机采样可能导致 FP32 和 INT8 即使分数接近，也选择不同 Token。因此统一采样实验使用贪心 argmax；实验结束后已恢复原来的随机采样代码。

### 实验二相关问题：FPGA 尚未完成当前版本的独立验证

目前的 mismatch=0 主要是 Python 自一致性结果。真实 FPGA/RTL 逐层比较、板上 Token 输出和当前版本的 200 Token 验证仍需后续完成。
